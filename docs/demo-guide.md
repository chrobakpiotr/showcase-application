# Demo guide

[Technical setup](../README.md) | [Domain and business rules](domain-guide.md) | [AI scenarios](ai-guide.md)

This repository is meant to be explorable, not just compilable. The local IDE profiles and the `docker` Spring profile explicitly enable a dedicated Liquibase `demo` context, which loads
deterministic catalog, stock and coupon data on a fresh database. Kubernetes does **not** enable `demo` by default, so a
cluster or other profile stays unseeded unless it deliberately opts in.

## Fastest path

```bash
docker compose up -d --build
```

Open `http://localhost:9080/home` and sign in with:

| User | Password | Purpose |
|---|---|---|
| `order-admin` | `password` | full showcase operator access |
| `order-viewer` | `password` | read-oriented operator experience |

Start with **Catalog**. Every demo product exposes a stable `DEMO-*` SKU that can be pasted directly into Inventory,
Orders, Reviews, Wishlist or Swagger calls.

## Seeded coupons

| Code | Type | Value | Minimum order |
|---|---|---:|---:|
| `SAVE10` | percentage | 10% | 50.00 |
| `WELCOME20` | percentage | 20% | 100.00 |
| `FLAT15` | fixed amount | 15.00 | 75.00 |

Coupon rows are demo fixtures, but redemption counters are real application state. A reused local database therefore
keeps whatever redemption count previous runs produced.

## Useful demo scenarios

### Catalog → Inventory

1. Open **Catalog** and copy any `DEMO-*` SKU.
2. Open **Inventory** and load that SKU.
3. Receive, reserve, release or fulfill stock as `order-admin`.
4. Reload the same SKU and observe optimistic-lock-backed state changes.

### Catalog → Cart → Coupon

1. Open **Catalog** and choose a product.
2. Open **Cart**, create a cart and add the product SKU.
3. Add more products until the order value reaches a coupon threshold.
4. Apply `SAVE10`, `WELCOME20` or `FLAT15` and compare totals.

### Catalog → Order → Payment → Shipment / Return

1. Use one or more seeded SKUs when placing an order. The corresponding stock already exists.
2. Open **Order History** and inspect the order and payment state.
3. Use **Shipments** to create/advance fulfillment, or **Returns** to exercise the reverse flow.
4. Inspect **Notifications** for customer-facing events generated by those transitions.

### Reviews and recommendations

1. Submit reviews against a seeded SKU.
2. Moderate pending reviews as `order-admin`.
3. With the optional Ollama profile enabled, use the recommendations screen with customer/order/review data you created.

## Resetting demo state

For the containerized stack, a clean database is the most predictable reset:

```bash
docker compose down -v
docker compose up -d --build
```

That recreates the database and reapplies the Liquibase demo changesets. Do not use this command if the local Docker
volumes contain data you want to keep.

For H2 local runs, restarting the in-memory database is enough.

## Why the fixtures live in Liquibase

The data uses the same schema lifecycle as the application, appears before the UI becomes usable, and works identically
with the local H2 and Docker/Postgres profiles. Stable SKUs are more useful for manual testing and documentation than
random data generated by a startup runner. The fixtures use the required `@demo` Liquibase context, so a deployment must explicitly opt into `demo` before the seed
is eligible to run. Local IDE profiles and Docker Compose do; Kubernetes intentionally does not.

## Demo data

The local IDE profiles and the `docker` showcase profile explicitly enable a dedicated Liquibase `demo` context. A fresh
demo database therefore starts with **12 stable `DEMO-*` products**, matching Inventory stock and three useful coupon
codes (`SAVE10`, `WELCOME20`, `FLAT15`). This makes Catalog, Cart, Inventory and Order scenarios usable immediately
in developer/demo environments instead of forcing manual setup before every tour.

The fixtures are tied to required `@demo` changesets. Kubernetes intentionally does **not** enable the `demo` context by
default, so pointing the application at a cluster or external database does not silently populate showcase fixtures. See
[seeded catalog and stock](#seeded-catalog-and-stock), [reset instructions](#resetting-demo-state)
and [demo scenarios](#useful-demo-scenarios) for the complete walkthrough.
