# Real-stack k6 smoke

Date 2026-11-11. Run by the owner on a MacBook Pro (darwin/amd64) with k6 v2.3.0 against a fresh Docker Compose
stack built from `main` after `git pull` to `10b80f3`. The agent did not confirm the checkout revision independently.
Command: `k6 run -e ITERATIONS=20 -e VUS=2 tooling/load-testing/order-api.js` with an `order-admin` token from a
Keycloak browser session. The token is not recorded.

## Result

Exit code 0. All thresholds passed.

| Metric | Value | Threshold |
|---|---|---|
| checks | 100%, 62 of 62 | rate == 1 |
| iterations | 20 of 20 | count == 20 |
| http_req_failed | 0%, 0 of 42 | rate < 0.01 |
| place_order_duration p95 | 406.37 ms (avg 102.28, med 63.39, max 439.63) | < 1000 ms |
| find_order_duration p95 | 84.68 ms (avg 30.36, med 20.6, max 117.98) | < 500 ms |

The run took 11.6 s. Every order used the same customer email, so it confirms AC-001 and AC-002 end to end on the
real stack. This is the first p95 baseline for this environment: one developer laptop, two virtual users, not a
capacity measurement.

The run before the fix, on the same day, failed with HTTP 500 and is recorded in the
[SHOWCASE-FOLLOWUP-001 hosted CI record](../../SHOWCASE-FOLLOWUP-001/evidence/hosted-ci-2026-11-11.md).
